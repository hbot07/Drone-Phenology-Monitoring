Drone Phenology Monitoring

From orthomosaics to phenology curves

Upload a series of georeferenced drone orthomosaics, each from a different date, press Run, and the pipeline does the rest: it delineates every tree crown, links the same tree across all your survey dates, measures its greenness through time, and builds an interactive viewer where you can click any crown and see its seasonal curve.

The four steps below show exactly what happens under the hood. Every step reads a shared pipeline_config.json and writes outputs the next step consumes — so if any step fails, you can re-run from that point without redoing earlier work.

Step 0 is the pipeline's bootstrap. It reads your uploaded .tif files, matches each to the acquisition date you entered on the dashboard, and produces a pipeline_config.json that every later step reads. Nothing else happens until this file exists.

What it does

  • Internally renames files to sit_DD-MM-YY.tif so they sort chronologically — your original filenames are always shown in the dashboard.
  • Records tile geometry (width, height, buffer) for the detector in Step 1.
  • Writes every path the pipeline will produce, so later steps know where to read and write without any further configuration.
  • Auto-detects the project root or uses the path the server injects.
Reads
  • Uploaded .tif files
  • User-entered acquisition dates
  • Tile width, height, buffer params
Writes
  • pipeline_config.json
  • Renamed sit_*.tif files

The most compute-intensive step. For every orthomosaic in your series, Detectree2 — a Mask R-CNN model fine-tuned on drone canopy imagery — predicts a polygon for each tree crown visible from above. It runs on GPU if available, otherwise CPU (much slower).

How tiling works

  • Each orthomosaic is cut into small overlapping tiles (controlled by tile width, tile height, and buffer).
  • The model runs inference on each tile independently and outputs per-tile polygon sets.
  • Overlapping predictions from adjacent tiles are merged: the IoU threshold controls how aggressively near-duplicates are removed.

Output confidence thresholds

The model outputs crowns at multiple confidence levels. These are stored as tagged GeoPackage files (e.g. _conf_0p45_multithreshold.gpkg), one set per date. Step 2 picks which confidence level to use for tracking via the threshold tags.

Reads
  • All sit_*.tif orthomosaics
  • Detectree2 model weights (.pth)
Writes
  • Per-date multi-threshold crown GeoPackages
  • 01_detectree/ folder

Detection gives you a set of crown polygons per date, but the pipeline needs to know which polygon in date 3 is the same tree as polygon 47 in date 1. Crown tracking does exactly that: it aligns the dates against each other and links corresponding crowns into temporal chains.

Alignment

  • Each Orthomosaic is registered to the next using high-confidence anchor crowns (controlled by the align threshold). Only very confident, stable detections are used as anchors — they're less likely to move between dates.
  • Registration uses phase-cross-correlation on tiled windows (pcc_tiled), which is robust to slight GPS offsets and wind movement.

Chain building

  • At the base threshold, crowns are matched date to date by spatial overlap.
  • Each resulting chain is a list of (date, polygon) pairs representing one physical tree over time.
  • A consensus polygon is derived for each chain — the stable median footprint of that tree across all dates it was detected.
Reads
  • Per-date crown GeoPackages from Step 1
Writes
  • Crown chains GeoJSON
  • Consensus crowns GeoPackage
  • 02_tracking/ folder

For every tree chain, Step 3 extracts a time series of spectral and texture measurements from the orthomosaics inside the consensus crown boundary. These signals are combined into a deciduousness score that separates seasonally-leafing trees from evergreens, then a classifier labels each (tree, date) pair with a discrete phenophase.

Signals measured per tree per date

  • Vegetation fraction — HSV-based greenness, normalised within the crown.
  • GCC — Green Chromatic Coordinate, a colour-ratio index robust to illumination changes.
  • Texture — Laplacian variance, measuring how "rough" the canopy surface looks (bare branches vs dense leaves).

Deciduousness score (DS)

DS combines the seasonal amplitude of four signals with user-adjustable weights: DS = w_veg_amp·s_veg + w_depth·s_depth + w_gcc_amp·s_gcc + w_tex·s_tex. Trees above the DS threshold are classified as deciduous and sent for phenophase labelling; the rest are assigned leaf-on for all dates.

Phenophase classification

  • A gradient-boosting model (HistGradientBoosting) predicts phenophase — leaf_on, leaf_off, or transitioning — from local-trough features built on the greenness curves.
  • Evergreen trees (DS below threshold) are automatically assigned leaf_on for every date.

Temporal smoothening

  • Short isolated label runs — a single date labelled leaf_off sandwiched between leaf_on dates — are corrected by flipping them to match their neighbours.
  • A confidence gate prevents flipping labels where the model was very certain (controlled by flip_below).

Derived events

From the smoothed per-OM labels, three event dates are derived per tree: leaf-off start, full leaf-off, and leaf-on return. These are written back into the GeoJSON under classification.

The viewer needs the orthomosaics in a format a web browser can load efficiently at any zoom level. This step converts each orthomosaic to a Cloud-Optimized GeoTIFF, pre-renders an XYZ tile pyramid, then assembles a self-contained interactive map combining the tiles, crown layer, and classified phenology data.

COG conversion

A Cloud-Optimized GeoTIFF stores data in a layout that allows a client to fetch only the pixels it needs for the current view, instead of downloading the whole file. Each orthomosaic is renamed to OM01_*.tif to match its order in the series.

XYZ tile pyramid

  • Tiles are rendered from zoom 10 to the max zoom you set (typically z22 = native 5 cm/px).
  • Each tile is a z/x/y.png file at 256×256 px (the web standard).
  • A tile manifest records the bounds, zoom range, and which date is the default underlay.

What you can do in the viewer

  • Pan and zoom over the study site at full drone resolution.
  • Switch dates — each orthomosaic is a separate layer you can toggle to see the canopy at different points in the season.
  • Click a crown to open a popup with its chain ID, deciduousness score, and a per-date phenophase timeline.
  • Filter by phenophase — highlight leaf-off crowns, transitioning crowns, or evergreens.

Sharing

Because the viewer is a single HTML file with all data embedded or referenced locally, you can copy the 04_viewer/ folder to any web server (or share the ZIP) and it will work without any backend.
