DPM runs a seven-step pipeline on every uploaded orthomosaic set. Each step writes its outputs to a run-specific folder and the next step picks them up automatically — you do not need to move any files.

Overview

Step 1 — Crown Detection

1

Crown Detection

01_crown_detection.py
in Orthomosaic GeoTIFFs out Per-date crown GeoJSONs

A sliding window passes each orthomosaic through a fine-tuned YOLOv8 model that draws a bounding box around every visible tree crown. The model was trained on canopy imagery from multiple sites so it generalises across species and illumination conditions.

The tiling parameters (tile_width, tile_height, tile_buffer) control how the raster is sliced for inference — smaller tiles use less GPU memory but increase edge artefacts. After detection, boxes that overlap significantly (controlled by iou_threshold) are merged so each physical crown is represented once.

Output: one detections_<date>.geojson per input raster, each polygon carrying the detection confidence score.

Step 2 — Crown Tracking

2

Crown Tracking

02_crown_tracking.py
in Per-date crown GeoJSONs out Tracked crown time-series GeoJSON

Crowns from different dates are linked into persistent identities — a single tree gets the same ID across all acquisition dates even if the drone flew a slightly different path or the GPS drifted. Tracking works in two sub-steps.

Alignment: A subset of high-confidence, spatially stable crowns (selected using align_threshold) serves as ground-control anchors. The remaining crowns from each date are warped to match the reference date.

Association: After alignment, crowns are matched across dates using IoU and centroid distance. Only crowns that appear in at least as many dates as the base_threshold parameter requires are kept — this filters out false detections and transient objects (vehicles, shadows).

Output: tracked_crowns.geojson — one feature per tree, with a per-date geometry and spectral values array.

Step 3 — Phenology Analysis

3

Phenology Analysis

03_phenology_analysis.py
in Tracked crown time-series GeoJSON out Per-crown phenology metrics GeoJSON

For each tracked crown, the pipeline extracts a time series of vegetation indices — primarily the Green Chromatic Coordinate (GCC) and mean vegetation band intensity — from the orthomosaic pixels inside that crown's polygon at each date.

A double-logistic curve is fitted to the time series. Key phenological transition dates are derived from that curve: Start of Season (SOS), Peak of Season (POS), and End of Season (EOS). These are the numbers shown in the interactive viewer tooltips.

Output: phenology_metrics.geojson — the tracked crowns enriched with SOS, POS, EOS and derived Deciduousness Score (DS) fields per crown.

Step 4a — COG Tiling

4a

COG Tiling

04a_cog_tiling.py
in Orthomosaic GeoTIFFs out Cloud-Optimised GeoTIFFs

The raw orthomosaics are reprojected, overviewed, and tiled into Cloud-Optimised GeoTIFF (COG) format. The COG internal structure means the interactive viewer can request only the tiles it needs at the current zoom level, rather than downloading the full raster.

The zoom parameter sets the highest detail level to pre-build. Each additional zoom level doubles the tile count, so higher values grow the output folder substantially. The tilesize parameter (default 256 px) controls the pixel dimensions of each map tile.

Output: one COG per input date, stored under cogs/ inside the run folder.

Step 4b — Interactive Viewer

4b

Interactive Viewer

04b_interactive_viz.py
in COGs + Phenology GeoJSON out Leaflet map HTML

Assembles the per-date COG tiles and the phenology GeoJSON into a self-contained Leaflet.js web map. Each crown polygon is clickable: the tooltip shows the tree's tracked ID, phenological transition dates, and a small time-series chart.

A date slider at the bottom lets you step through acquisition dates; the basemap switches between the raw orthomosaic and a false-colour vegetation index view. The output is a single viewer.html file that references its tiles relatively and can be opened in any browser.

Step 10 — Phenophase Classifier

10

Phenophase Classifier

10_phenophase_classifier.py
in Phenology metrics GeoJSON out Per-crown phenophase labels

Classifies each tracked crown as deciduous, evergreen, or mixed/ambiguous based on a weighted combination of the phenological metrics computed in Step 3. The Deciduousness Score (DS) is a linear combination of:

  • Vegetation amplitude (w_veg_amp) — how much the canopy greens up
  • Dormancy depth (w_depth) — how bare the tree becomes at winter minimum
  • GCC amplitude (w_gcc_amp) — colour-based green-up signal
  • Texture amplitude (w_tex) — structural change through the season

See the Parameter Guide → Step 10 section for guidance on tuning the weights for your site.

Step 12 — GeoJSON Export

12

GeoJSON Export

12_apply_phenophase_to_geojson.py
in Phenophase labels out Final annotated GeoJSON

Merges the phenophase classification back into the tracked crown polygons and writes the final annotated GeoJSON. This is the file the viewer loads and the primary deliverable for downstream GIS analysis.

Each feature in the output carries the crown geometry, all phenological metrics (SOS, POS, EOS, DS), the phenophase label, and the full per-date spectral value array — everything needed for further analysis in QGIS, Python, or R.

Final outputs

Where to find your results: Open the run from the dashboard and click Browse files to explore the run folder. The most useful files are final_annotated_crowns.geojson (all crowns with phenophase labels, ready for QGIS), viewer.html (the interactive map), and phenology_metrics.geojson (raw metrics before classification).
