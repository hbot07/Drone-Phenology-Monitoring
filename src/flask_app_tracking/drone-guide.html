The pipeline was developed and validated on surveys flown with Map Pilot Pro (iOS) and processed in WebODM. Any photogrammetry workflow that produces a georeferenced GeoTIFF orthomosaic will work — these are recommended settings, not requirements.

Requirements

  • Multispectral or high-resolution RGB drone (RGB orthomosaics work; multispectral adds accuracy)
  • Ground sampling distance (GSD) ≤ 10 cm/px — 5 cm/px or better is recommended
  • At least 5 acquisition dates, spread across the phenological season
  • Consistent flight boundaries across all dates — the same area must be covered every flight
  • Surveys flown within ±2 hours of solar noon for consistent illumination
⚠ Illumination consistency matters. Large shadows from low sun angles introduce spectral noise that degrades phenological signal extraction. Overcast conditions are often better than bright sun near sunrise or sunset.

Planning the mission

Draw your survey area once and save the mission file — reuse the exact same polygon every flight date. This keeps the orthomosaic extents consistent across dates, which makes crown tracking much more robust.

1
Open Map Pilot Pro (or your preferred app)

Create a new grid mission. Import a KML/KMZ boundary if you already have one from a previous survey.

2
Set the survey polygon

Draw or import the boundary of the forest plot. Add 20–30 m buffer beyond the outermost trees so edge crowns are fully captured.

3
Configure flight parameters

See the table below. For most sites, 80 m AGL with 80/70% overlap produces a 4–5 cm/px GSD on a DJI Phantom 4 Pro or Mavic 3.

4
Save and sync the mission

Save the mission file to iCloud or a shared folder so you can reload the same plan on every return visit.

Flight parameters

ParameterRecommended valueNotes
Flight altitude (AGL)60–100 mLower = finer GSD but longer flight time. 80 m is a good default.
Front overlap80%High overlap compensates for canopy texture in SfM reconstruction.
Side overlap70–75%Can reduce to 65% if battery is limiting, but check edge quality.
Flight speed5–7 m/sSlower in wind. Motion blur above 8 m/s is visible at 5 cm/px.
Camera angleNadir (90° / straight down)Do not use oblique — the pipeline assumes nadir imagery.
Image formatJPEG fine or RAW+JPEGRAW enables white-balance correction in post; JPEG fine is sufficient for RGB runs.
White balanceSunny / fixed (not Auto)Auto white balance changes the colour between images and corrupts GCC signal.
ISO100–200Keep low to minimise noise. Increase only in heavy overcast.
Shutter speed1/800 s or fasterPrevents motion blur at typical drone speeds. Use Auto-ISO to compensate for faster shutters.

Flying the mission

  • Check NOTAM and local airspace restrictions before every flight
  • Calibrate the compass and IMU on the ground before the first flight of the day
  • Fly the automated grid mission — do not interrupt or re-start mid-mission
  • Note the exact takeoff time and date (UTC) — you will need this for the DPM acquisition date field
  • If the drone returns to home before completing the grid, note the last covered row; re-fly the missed strip before landing
  • Download images immediately after landing; check for blur, exposure issues, or gaps in coverage

Building the orthomosaic in WebODM

WebODM (or ODM) is the recommended photogrammetry tool. Other tools (Pix4D, Metashape) also work — export a single-band-per-channel GeoTIFF in EPSG:4326 or a local UTM projection.

1
Create a new task

Upload all images from one flight date as a single task. Do not mix images from different dates.

2
Select the "High resolution" preset

Or set feature-quality: ultra, min-num-features: 12000, depthmap-resolution: 640 manually.

3
Enable orthophoto generation

Ensure Orthophoto is checked. Disable 3D model outputs if disk space is limited.

4
Download the GeoTIFF

After the task finishes, download odm_orthophoto.tif. This is your input file for DPM.

5
Verify the file opens in QGIS

Check that it is georeferenced (coordinate system shown in layer properties) and that colours look correct before uploading.

Quality checklist before uploading

  • GSD ≤ 10 cm/px (check in QGIS: Layer Properties → Information → Pixel size)
  • Full coverage of the site — no black or grey patches at the edges or inside the canopy
  • Colours look natural and consistent across the scene
  • File is a multi-band GeoTIFF (.tif / .tiff) with at least 3 bands (RGB)
  • File is georeferenced — projection shown in QGIS, not "Unknown CRS"
  • File size is reasonable — a 5 cm/px 500 m × 500 m area is typically 50–300 MB
Tip: Name each orthomosaic with the acquisition date, e.g. site_2024-03-15.tif. DPM accepts any filename but the date field in the upload form must still be filled in manually — a clear filename makes it harder to enter the wrong date.

Uploading to DPM

1
Go to New Run

Click New Run on the dashboard. Give the run a short, recognisable name.

2
Upload your GeoTIFFs

Drag all orthomosaics for this site (all dates) into the file drop zone. You can upload them all at once.

3
Enter acquisition dates

For each file, enter the date the flight was flown (DD/MM/YYYY). This date drives all phenological calculations — accuracy matters.

4
Leave parameters at defaults

First-time users should leave all advanced settings unchanged. Consult the Parameter Guide only if results look wrong.

5
Click Upload & start pipeline

The seven pipeline steps will run on the server. You can track progress on the dashboard or close the tab and return later.

Repeat survey guidance

The quality of phenological metrics depends heavily on the temporal coverage and spacing of your survey dates.

AspectRecommendation
Minimum dates5 — fewer dates produce unreliable curve fits
Ideal dates8–12, spaced 2–3 weeks apart through the active season
Season coverageStart before leaf-out; end after full leaf-off. Missing either end degrades SOS/EOS accuracy.
Inter-date interval2–4 weeks. Shorter intervals give smoother curves; longer gaps may miss key transitions.
Time of dayWithin ±2 hours of solar noon, same window on each date
Boundary consistencyReuse the exact saved mission file — any expansion of the survey area changes crown IDs
Expanding an existing run: If you acquire new dates for a site you have already analysed, start a new run that includes all dates (old + new). There is currently no incremental update mode — re-running with the full date set re-computes all crown tracks from scratch, which ensures consistency.
